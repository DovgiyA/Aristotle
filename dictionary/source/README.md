# Исходник Словаря Сети версии 1

Данные, а не код программы (DICT-01): из этого каталога команда `aristotel dictionary build`
собирает неподписанную версию Словаря Сети (research R5 фичи 005). В поставку программы каталог не
входит: Словарь приходит на Опорную станцию подписанной версией (DICT-16, DICT-17).

Каталог собирает генератор из приложения «Словарь Сети v1»:

```bash
node tools/slovar/from-appendix.ts docs/spec/slovar-seti-v1.md dictionary/source <каталог первоисточников>
```

Руками файлы не правятся: контрактный тест `tests/contract/dictionary-source.test.ts` сверяет каталог
с выводом генератора по текущему приложению.

| Файл | Что в нём |
|---|---|
| `types.json` | типы объектов (§1), связей (§2), Индикаторов (§6) |
| `enums.json` | перечни (§7) |
| `classes.json` | Классы изделий, подтип (§3) и шаблоны Формуляра (§9) |
| `merges.json` | склейки (`synonyms`, `localTypes`) и устаревшие элементы (`deprecated`) этой версии, смена Кода с тем же Идентификатором (`renamed`: `{ from, to }`, Коды «вид:код»); состояния прежних версий сборка переносит сама; у версии 1 — пусто |
| `stop-lists.json` | все семь списков Стоп-листа §8: Код, Подпись, раздел, первоисточник, число строк |
| `stop-lists/<код>.json` | списки Стоп-листа §8.1, §8.3, §8.4, §8.5 в формате `aristotel/stop-list/v1` |

Списки §8.2, §8.6, §8.7 значений в приложении не несут: их собирает Сборщик Стоп-листа (фича 023)
и отдаёт файлами того же формата — `aristotel dictionary build --stop-list <файл>`.

## Перечни по внешним стандартам

Приложение задаёт их ссылкой на стандарт; в исходник они входят явными списками из закреплённых
выпусков первоисточников:

| Перечень | Первоисточник | Выпуск |
|---|---|---|
| `timezone` | IANA tzdata: `zone1970.tab`, `zone.tab` — зоны, `backward` — ссылки на прежние имена | 2026e |
| `country` | IANA tzdata: `iso3166.tab` — коды ISO 3166-1 alpha-2; плюс `00` | 2026e |
| `keyboard` | xkeyboard-config: `rules/base.xml` — раскладки верхнего уровня | 2.48 |
